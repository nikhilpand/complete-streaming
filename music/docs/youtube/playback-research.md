# YouTube Playback Architecture & Reality

## 1. Reality of YouTube Audio Streams

### Critical Fallacies to Reject
1. **"YouTube provides permanent audio URLs"**: `[CONFIRMED FALSE]`
   - Every audio stream URL generated by Google Video Server (`googlevideo.com/videoplayback`) is ephemeral and cryptographically signed.
   - The query string includes an explicit `&expire={unix_timestamp}` parameter (typically valid for 6 hours).
   - Attempting to play or cache a URL past its expiry yields an immediate HTTP 403 Forbidden.
2. **"ytmusicapi provides audio streams"**: `[CONFIRMED FALSE]`
   - `ytmusicapi` is an Innertube metadata client only. It does not resolve direct audio stream URLs.
3. **"YouTube Music serves 320kbps MP3s"**: `[CONFIRMED FALSE]`
   - Free/public YouTube Music streams cap at:
     - **Opus (format 251)**: ~140-160 kbps (48,000 Hz, webm container)
     - **AAC (format 140)**: ~128 kbps (44,100 Hz, m4a container)
     - **Low-bitrate AAC/Opus (formats 139, 249, 250)**: ~48-75 kbps
   - Declaring a stream as "320kbps" without verified extractor metadata is a false representation.

## 2. Format Classification & Selection Algorithm

`YouTubePlaybackResolver` enforces real format discovery:

```
Raw Formats from Extractor
           │
           ▼
[Filter 1]: Valid URLs Only (exclude DRM/SABR without direct HTTP stream)
           │
           ▼
[Filter 2]: Audio-Only (vcodec == 'none' && acodec != 'none')
           │
           ▼
[Filter 3]: Quality Bucket Matching
  - auto:   Prefers highest bitrate compatible audio (format 140 m4a or 251 opus)
  - high:   abr >= 120 kbps (prefers format 251 opus or 140 m4a)
  - medium: 70 kbps <= abr < 120 kbps (format 250)
  - low:    abr < 70 kbps (formats 139, 249)
           │
           ▼
[Filter 4]: Container / Codec Compatibility Preference
  - m4a / mp4a: Highest cross-platform browser compatibility
  - webm / opus: Higher acoustic fidelity per bitrate
           │
           ▼
Selected PlaybackSource
(Url, Quality, Bitrate, Codec, Container, ResolvedAt, ExpiresAt)
```

## 3. Cache Lifetimes & Safety Margin

Playback URLs must **never** be cached alongside song metadata:

```
┌─────────────────────────────────┬─────────────────────────────────┐
│ SongMetadataCache               │ PlaybackResolutionCache         │
│ - Key: yt:song:{video_id}       │ - Key: yt:playback:{video_id}:q │
│ - TTL: 3600s (1 hour)           │ - TTL: Min(remaining_ttl, 300s) │
│ - Data: Title, artist, album    │ - Safety Margin: 300s (5 min)   │
└─────────────────────────────────┴─────────────────────────────────┘
```

### Expiry Check Before Return:
```python
remaining_seconds = expires_at.timestamp() - now.timestamp()
if remaining_seconds <= SAFETY_MARGIN_SECONDS:
    # Stale: re-resolve fresh stream URL from upstream
```

## 4. In-Flight Deduplication (`PlaybackResolutionDeduplicator`)

Because `yt-dlp` extraction is computationally expensive ($\sim 1-3$ seconds per call) and network heavy:
- If 20 simultaneous requests arrive for `GET /api/v1/youtube/playback/fsiPzT50ZiM?quality=high`:
- A single `asyncio.Future` is registered for `(video_id, quality)`.
- Only **one** `yt-dlp` thread job is launched.
- All 20 callers await the identical future.
- When the job completes, the future resolves for all callers and is removed from the active registry.
- Prevents extraction storms, CPU spikes, and upstream rate limits.
